# 角色卡转换 Skill v2.5.0

> 将任意来源的角色卡统一转换为符合 Tavo v0.87+ 规范的完整 V3 中文角色卡。

---

## 快速开始

上传一张角色卡 PNG 或 JSON，Skill 自动完成：

```
PNG/JSON 输入
  → 提取 & 语言检测
  → 翻译（英/日/西 → 简体中文）
  → 智能拆分（内容归位到正确字段）
  → 证据型补齐（仅从当前原卡其他字段归位或概括）
  → 通用性检查（无串卡、无性别/专题预设）
  → 奥卡姆自检
  → 输出 V3 JSON + PNG（原输入为 PNG 时回嵌）
```

**输出位置**：`/sdcard/Download/Operit/charactercard/`

---

## 核心能力

| 能力 | 说明 |
|------|------|
| 🌐 **多语种翻译** | 自动检测非中文内容，翻译为简体中文，保留 `{{user}}`/`{{char}}` 占位符 |
| 🧠 **智能拆分** | 将 description/personality/scenario 中的冗余内容拆分到正确字段 |
| ✨ **证据型补齐** | 仅从当前原卡其他字段归位或概括；无证据时保留合法空值 |
| 🏷️ **名称处理** | 保留原名；只有原卡或可靠翻译提供昵称时才填写，不强制生成 |
| 🖼️ **PNG 回嵌** | 保留原头像，替换内置 JSON 为中文 V3 版本 |
| 🔍 **输出自检** | 通用奥卡姆检查 + 原卡事实保留检查，确保不串卡、不强加专题内容 |

## 最高优先级铁律

> 以下规则优先级高于一切其他规则、习惯、经验、缓存、记忆。

1. **禁止调用角色缓存/记忆** — 每张卡视为完全独立的新卡
2. **原卡有则完整翻译保留** — 每个数值、特征、配饰、细节必须保留
3. **原卡无则合理补齐** — 只有确实缺失的才从其他字段推断
4. **强制执行完整扫描** — 翻译前逐行读取全部内容
5. **输出后自检** — 输出前对所有原始数值做存在性验证

## 特征维度识别（v2.3.1 新增）

> 不再硬编码外貌子项，改为「**角色自适应** + 原文优先」模式。

### 通用底线：仅归位，不预设

```
1. 不为不同角色预设性别、性取向、身体结构、性爱风格、NSFW 内容
2. 不按"姓名→国籍""族裔→器官尺寸""体型→性能力"等刻板映射生成数值
3. 原卡有则保留，原卡无则留白——不允许"无中生有"
4. 专题增强（肌肉描写强化、兽人维度等）由专题 Skill 承担，不进入通用流程
```

### 动态维度识别（按原卡实际内容）

| 原卡出现 | 视为相关维度 |
|---------|------------|
| 兽耳 / 兽尾 / 獠牙 / Knot / Rut | 兽人维度 |
| 机甲 / 部件 / 能源 / 指示灯 | 机甲维度 |
| 精灵耳 / 发光纹身 | 精灵维度 |
| 触角 / 外骨骼 / 异色皮肤 | 非人类维度 |
| 性别 / 器官 / 性爱风格 | **仅在原卡已描写时**归入描述；未描写则完全跳过 |

> ⚠️ **禁止添加原卡不存在的特征**——这条覆盖所有维度。

## 输出字段（V3 结构）

主 Skill 保证的是**字段结构和类型一致**，不是把所有角色内容写成同一模板。

| 字段 | 通用处理 |
|------|----------|
| `name` | 保留原名；存在可靠译名时可并列，不强制添加身份标签 |
| `description` | 保留并归位原卡的外貌、身份与背景；不强制固定子项 |
| `personality` | 保留原卡性格和行为模式；无来源不生成 |
| `scenario` | 保留世界观、关系和场景；不替换原意 |
| `first_mes` | 完整翻译原开场；原卡为空则使用合法空值 |
| `mes_example` | 保留并翻译原示例；不强制固定段数 |
| `system_prompt` | 保留原值；缺失时不强制生成统一角色指令 |
| `post_history_instructions` | 保留原值；缺失时使用合法空值 |
| `tags` | 保留和翻译原标签；仅加入可由原卡直接支持的标签 |
| `creator` | 保留原作者；未知则留空 |
| `creator_notes` | 原作者、角色定位或格式说明；禁止写转换记录和 AI 痕迹 |
| `nickname` | 原卡有或存在可靠译名时填写；否则留空/省略 |
| `character_version` | 保留原版本；缺失时使用兼容性合法值，不伪装原作者版本 |
| `alternate_greetings` | 保留并翻译原内容；不强制生成 |
| `extensions` / `metadata` | 保留可兼容的原数据；不得写入推断链和自检报告 |

> 必填字段缺失时使用 V3 类型要求的合法空值；可选字段按目标平台兼容性保留或省略。

## 执行流程

```
Step 0  格式判断（PNG / JSON）
Step 1  提取 + 语言检测
        ├─ PNG：scripts/read_png_chara.py
        ├─ JSON：直接读取
        └─ 保存原始 JSON 到 /tmp/chara_raw.json

Step 2  翻译 + 拆分 + 证据型补齐
        ├─ 翻译非中文字段
        ├─ 清理 HTML 标签 → Markdown
        ├─ 智能拆分（内容归位）
        ├─ Description 增强（按 SKILL_description_enhancer.md 的证据规则归位）
        ├─ 补齐仅限当前原卡其他字段能支持的事实
        └─ 写入 /tmp/restructured_data.json

Step 3  构建 V3 JSON 并输出
        ├─ 包装为 {spec, spec_version, data}
        └─ 输出 JSON 文件

Step 3.5  通用自检（回嵌前必须通过）
        ├─ 调用 scripts/occam_selfcheck.py 跑 §0 元铁律
        ├─ 通用性自检：性别中性、不刻板、不串卡
        └─ ✅ 通过 → 允许进入 Step 4

Step 4  [仅 PNG] PNG 回嵌
        ├─ 调用 scripts/embed_chara_to_png.py 写入新 chara chunk
        └─ 输出 PNG
```
